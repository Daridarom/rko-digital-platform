# Cosmatica: полные шаблоны публикации, мероприятия и проекта

Цель: передать в действующую CMS не монолитный HTML с жёстко зашитым содержанием, а **три полноценных адаптивных компонента**, которые получают структурированную запись из базы.

## Предварительный просмотр

В GitHub Pages новые шаблоны доступны отдельно от утверждённых 32 экранов. Это важно для безопасной сверки: существующая сборка сохраняется, новые страницы сравниваются до принятия.

**Внимание:** в отсутствие записей CMS страницы показывают сокращённые данные из `content.js` — они не являются полной миграцией первоначального текста. Режим `layout=full` означает полную *структуру шаблона*, а не подтверждение полноты наполнения.

## Архитектура

- `rich-renderer.mjs` — изолированные рендеры для публикации, события, проекта и общая библиотека текстовых блоков;
- `rich-preview.mjs` — тонкий адаптер демонстрации: принимает структурированную запись `window.COSMATICA_MIGRATED_PAGES` либо короткую фикстуру;
- `rich-preview.css` — единая адаптивная и брендированная система (Roboto, логотип из исходных активов, без изменения фирменной символики);
- `cms-adapter.mjs` — безопасный нормализатор данных из существующей CMS;
- `extract-content.py` — экспорт исходных HTML-страниц в текстовые блоки в локальный, не включаемый в Git каталог.

## Контракт содержимого

Пример подключения из контроллера CMS:

```js
window.COSMATICA_MIGRATED_PAGES = {
  article: {
    type: 'article',
    title: cmsArticle.title,
    author: cmsArticle.author,
    publishedAt: cmsArticle.publishedAt,
    blocks: cmsArticle.blocks
  }
};
```

В продакшене данные передаются напрямую функции `createArticle(record)`, `createEvent(record)` или `createProject(record)`; глобальный объект нужен только для изолированного демопоказа.

`blocks` поддерживают `heading`, `paragraph`, `quote`, `list`, `table`, `image`, `file`, `separator`. Вложенные текстовые фрагменты сохраняют выделение и порядок, а ссылки в демоверсии не отправляют посетителя на сторонний сайт. Потоки из сотен блоков тестируются автоматически.

### Публикация

Предусмотрены заголовок, вступление, дата, автор, полные тематические блоки, оглавление с якорями, таблицы, цитаты, иллюстрации с подписями. Оглавление адаптируется для мобильного экрана.

### Мероприятие

Предусмотрены дата/время, место, формат, организаторы, отдельная программа, описание, участники, документы и архивная версия без фиктивных кнопок регистрации.

### Проект

Предусмотрены статус, направление, миссия, цели, подробная деятельность, команда, документы, новости, мероприятия и **три финансовых состояния**: `none`, `active`, `completed`. Полоса прогресса показывается только при подтверждённой положительной цели; без фактических данных сумма и проценты не выдумываются.

## Проверка

```bash
node --test integration/cms-adapter.test.mjs
node qa/rich-templates.mjs
```

Вторая проверка запускается из каталога сайта с локальным веб-сервером и Playwright; в GitHub Actions она выполняется автоматически в составе `cosmatica-demo.yml`.

В браузере проверяются экраны 1440×960 и 390×844, длинная статья из 125 блоков, мероприятие с 22 пунктами программы, проект с различными деталями и корректной суммой сбора, отсутствие переполнений, недействительных внешних ссылок и исключений JavaScript.

## До передачи Павлу как полностью готового содержимого

1. Локально выгрузить полный текст каждой исходной страницы в `integration/_exports` при наличии разрешений.
2. Сверить подзаголовки, иллюстрации, списки, ссылки, таблицы, документы, подписи, авторов и даты.
3. Отдельно проверить права на изображения, тексты, ссылки на скачивание и персональные сведения.
4. Заполнить `page-map.json` статусом `CONTENT_VERIFIED` только после зафиксированной редакторской приёмки.
5. Подключить существующие авторизацию, поиск и оплату в CMS — не переносить демоимитации.

**Не публиковать чужие полные тексты в GitHub Pages автоматически только потому, что экспорт технически работает.** Полный экспорт и копирование в production осуществляются после согласования прав и редакторской сверки.
