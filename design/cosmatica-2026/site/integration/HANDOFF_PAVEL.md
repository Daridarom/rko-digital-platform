# РКО · комплект передачи дизайна и публичного контента разработчику CMS

**Статус:** инженерный пакет на GitHub (демонстрация, а не замена работающей CMS).
**Источник структуры:** таблица «Макеты страниц cosmatica.org», предоставленная Павлом.
**Источник информации:** только публичные страницы https://cosmatica.org/.
**Приоритет:** сохранить весь доступный публичный текст, исходные названия, обложки, иллюстрации, видеоссылки, навигацию и поля; заменить только визуальное представление.

## Проверенный охват — 8 октября 2026
- Проанализировано **5 203** публичных адреса из карт сайта, постраничных архивов, глоссария и внутренних ссылок.
- **373** адреса дают HTTP 404 у РКО; **1** возвращает HTTP 403; **1** адрес участника возвращает общий шаблон без публичного профиля; **11** публичных адресов статей обнаружены в списках, но их текст пока не получен для переноса (при повторном обращении исходный сервер не ответил); **5** являются служебными маршрутами.
- В статической сборке сохранено **4 812** проверенных редакционных записей. **11 других публичных статей из реестра ещё не восстановлены**; нельзя объявлять перенос всех материалов полностью завершённым.
- Восстановлены **1 412** публичных видеовставок на доступных страницах (YouTube, VK Видео, Rutube и публичные плееры партнёрских площадок). Видео не копируются, плеер загружается только после действия посетителя.
- Источники книжных файлов остаются на сервере РКО; JSON хранит исходные `https://cosmatica.org/files/download/...`, PDF книг НЕ входят в сборку. Допускаются обычные редакционные документы, если Павел подтвердит их формат.
- 15 записей были извлечены с текстовым fallback из нестандартной структуры старой CMS: требуется особо внимательно проверить оригинальное форматирование на этих страницах, текст не сокращать.

## Способ переноса
1. Уточнить CMS, версию, систему переопределения шаблонов/темы, формат импорта и место хранения динамических данных.
2. **Не переносить статические JSON как вторую базу в CMS без необходимости.** В ideal-режиме CMS продолжает отдавать собственные публичные записи; новые шаблоны читают существующие поля из БД. JSON здесь служат контрольными снимками для проверки полноты и сохранения ссылок.
3. Сопоставить каждый `sourceUrl` с маршрутом CMS и существующим объектом; сохранить стабильные URL, SEO-метаданные, вложения, категории, участников, связи материалов.
4. Верстка должна обрабатывать все 31 типа, адаптивные сетки (320/390/768/960/1440), длинные заголовки и тексты, фотографии различных размеров и lazy load видео.
5. Кнопки скачивания книг НЕ должны формировать новый путь. Использовать действующие ссылки РКО либо идентичную отдачу того же endpoint.
6. Вход, регистрация, комментарии, пожертвования и приватные функции остаются на проверенных серверных модулях CMS. Макеты GitHub Pages не являются их работающей заменой.
7. Визуальную тему включать только после проверки в тестовом окружении; сохранить возможность отката.
8. После пробного переноса сверить контрольные URL, количество карточек, постраничность, поисковые результаты и метаданные с исходным публичным сайтом.

## Отдельные требования Павла из таблицы

- Разные левые колонки проектов для разных типов/статусов сбора — предусмотрены; реальные состояния и бизнес-правила берутся из CMS и требуют проверки с Павлом.
- «Поддержать РКО» — новые стили и восстановленные пять исходных текстовых абзацев; способ оплаты и окончательные юридические тексты должны подтвердить разработчик и представители РКО.

## Приёмка
- Проверки данных: `python3 qa/archive-integrity.py`.
- Проверка типов: `node qa/check.mjs`.
- Браузер: `node qa/archive-smoke.mjs`, `node qa/archive-browser-sample.mjs`, `node qa/editorial-smoke.mjs`, `node qa/mobile-refinement.mjs`, `node qa/original-book-links.mjs`.
- Дополнительный статус CI GitHub проверяется для конкретного коммита. Результат локальных проверок нельзя путать с фактической публикацией.
- Архив ZIP готовить по согласованию формата передачи: исключить кеш исходных HTML, `node_modules`, журналы, скриншоты тестов и любые непубличные данные.

Работающий сайт РКО и его CMS в процессе создания прототипа не изменяются.
