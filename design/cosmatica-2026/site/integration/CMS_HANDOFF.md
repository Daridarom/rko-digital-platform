# Cosmatica 2026 — контракт переноса интерфейсов в CMS

Статус документа: техническая передача шаблонов, **не подтверждение завершения всей редакционной миграции**. Дата сверки: 8 октября 2026.

## 1. Канонические источники

- Типы страниц и контрольные URL — `page-map.json` (31 ссылка, 32 интерфейса с двумя состояниями поиска).
- Текущая кодовая демоверсия — `../index.html`, `../view.html`, `../routes.js`, `../content.js`, `../site.js`.
- Дополнительные демонстрационные действия — `../demo-data.js`, `../demo.js`, `../demo.css`.
- Цвета и официальная символика — `../../BRAND_RULES.md` и `../../DESIGN_SYSTEM.md`.
- Фактические разрывы — `COVERAGE_AUDIT.md`.
- Независимый нормализатор данных и проверка — `cms-adapter.mjs`, `cms-adapter.test.mjs`.

**Главное правило:** действующая CMS является источником текста, авторов, документов, пользователей, дат, мероприятий, пожертвований и прав доступа. Демонстрационный `content.js` — не полноценная копия её базы.

## 2. Что переносить, а что переписать

| Слой | Перенос | Примечание |
|---|---|---|
| Фирменные цвета, логотип, типографика | Перенести без изменения канонических активов | Roboto; #FFCA38, #5D000F, #0D0C39; знак не обрезать |
| Каркасы `header`, `footer`, `pageHero`, `sectionCards` | Перенести в общий layout CMS | Удалить дублирование и inline-строки |
| Визуальные шаблоны 32 состояний | Сохранить, связать с CMS-маршрутами | Один тип шаблона может отображать множество записей |
| `content.js`, `demo-data.js` | Использовать как тестовые fixtures, не как данные production | Тексты неполные, числа требуют актуализации |
| `demo.js` | **Не переносить в production как есть** | Он после рендера переписывает ссылки, формы и части DOM |
| `view.html?p=...` | Заменить каноническими исходными URL | Оставить как удобный staging-маршрут |
| Регистрация и вход | Подключить существующую backend-систему | Сессия, CSRF, ошибки, защита от перебора |
| Пожертвования | Подключить существующего провайдера | Отдельная серверная проверка суммы, реквизитов, статусов |
| Поиск | Индекс CMS, пагинация и параметры фильтрации | Демоверсия ищет в локальной выборке, не в полном архиве |

## 3. Целевое разделение модулей

1. **Маршрутизатор CMS** принимает реальный URL, тип сущности и ID. Не подменяет неизвестный проект «Дружиной Гагаринцев» или неизвестный материал страницей «Об РКО».
2. **Адаптер** получает запись/коллекцию CMS, приводит её к согласованной структуре. Пример — `normalizeCmsPage(type, record)`. Он не имеет DOM, запросов к сети, платежных ключей и глобальных переменных.
3. **Слой отображения** получает готовую модель страницы и выводит компоненты в разрешённом визуальном языке. Отдельные блоки `paragraph`, `heading`, `quote`, `list`, `image`, `file` должны быть доступны длинным публикациям.
4. **Контроллер действий** подключает поиск, фильтры, календарь, формы и платежи к существующим системам; логика показа не должна притворяться обработчиком платежей.
5. **Тестовые fixtures** моделируют пустое/полное состояние, ошибки, разные типы проектов, отсутствие изображения и состояние сбора; никогда не заменяют актуальные данные.

Например, текущая ссылка `view.html?p=project&id=gagarincy` в демонстрации должна соответствовать `/projects/gagarincy` в production и получать полную запись проекта по существующему механизму сайта.

## 4. Ключевые модели

### Универсальная сущность

Обязательны `id`, `title`, `slug`, `type`. Дополнительно: `intro`, `blocks`, `related`, `images`, автор/дата/источник согласно типу. Полные материалы — в блоках содержимого, не в краткой аннотации.

### Проект

Поля: уникальный ID, статус, миссия, цели, тело проекта, герой/галерея, ответственные, участники, документы, новости, события, порядок участия.

Вид левой колонки зависит от `fundraising.mode`: `none`, `active`, `completed`. Для `active` требуются `target`, `raised`, валюта, актуальная серверная сумма и допустимость поддержки. Если сбора нет — кнопка пожертвования **не отображается**. Если нет подтверждённых файлов — не рисовать фиктивные действия «скачать».

### Публикация

Заголовок, автор, дата, полный поток типизированных блоков, иллюстрации и подписи, цитаты, списки, ссылки на источники, сноски, связанные материалы и метаданные поиска. В оригинальной большой статье десятки тысяч знаков: её нельзя передавать как два абзаца в `content.js`.

### Мероприятие и календарь

Дата/время с часовым поясом, тип очного/онлайн участия, программа, место, организаторы, докладчики, регистрация, материалы, события прошлого/будущего. Календарь должен отражать реальную неделю и месяц.

### Библиотека

Название книги, авторы, библиография, полное описание, обложка, файлы и их фактическая доступность. Нет файла — нет кнопки «скачать».

### Пользователь и контакты

Данные профиля показывать согласно правам и согласиям в существующей CMS; никаких контактных полей, не разрешённых к публичному показу.

## 5. Маршруты и миграция

`page-map.json` — сквозная таблица **исходный URL → тип страницы → demoRoute → обязательные поля → состояние проверки**. `resolveLegacyRoute` ищет точное соответствие для заданных контрольных URL; неизвестные адреса возвращают `null`, а не случайный шаблон.

Не изменять существующие SEO-пути без отдельной карты 301-редиректов и согласования. Сохранять канонические URL, хлебные крошки, заголовки и доступность прямой ссылки. Для новости, книги и проекта маршрутизатор должен принимать конкретный ID/slug и загружать соответствующую запись.

## 6. Устойчивость и безопасность

- Не вставлять непроверенный HTML исходных публикаций через `innerHTML`; если CMS отдаёт HTML, очищать его по серверной политике. Нормализатор использует текстовые блоки.
- Запретить чужие произвольные схемы для файлов и изображений (`javascript:`, `data:`, `//host`).
- Не хранить пароли, ключи платежей, токены и конфиденциальные данные в GitHub Pages, параметрах URL или fixtures.
- Внешние ссылки из CMS разрешать только после проверки назначения и редакторского решения; в демонстрации они не являются действующими действиями.
- Проверить с клавиатуры: табуляция, фокус, раскрытие/закрытие меню, доступность модалок и сообщений об ошибках.
- Контраст, масштабирование шрифта, `prefers-reduced-motion`, видимость герба и `object-fit: contain`.
- Перед переносом фотографий и текстов подтвердить права и актуальность первоисточника.

## 7. Закрытый цикл передачи

1. Получить полные записи/поля и материалы из CMS.
2. Провести постраничное сравнение `source` ↔ `staging` по `page-map.json` с фиксацией расхождений.
3. Подставить нормализованные данные в шаблоны, устранить оставшиеся имитации и недоступные кнопки.
4. Прогнать сборку (синтаксис/данные), адаптивность 320/390/430/1440, состояния, ссылки, изображения и взаимодействия.
5. Заполнить акт редакторской проверки каждой страницы (кто, дата, содержимое, медиа, ссылки, доступность).
6. Только после сверки выставить `CONTENT_VERIFIED` и передавать страницу на интеграцию в production.

Возможна передача по частям: сначала полностью завершённые базовые шаблоны, затем проекты и каталоги, потом объёмные статьи/мероприятия и наконец формы. **Число работоспособных демонстрационных экранов не равно числу редакционно готовых страниц.**

## 8. Проверки

Из каталога `design/cosmatica-2026/site`:

```bash
node qa/check.mjs
node --test integration/cms-adapter.test.mjs
```

Браузерные проверки в GitHub Actions выполняются отдельно. Эти тесты подтверждают схему и действия, но не могут автоматически подтвердить дословную полноту редакционных материалов — для неё обязателен пункт 7.5.

## 9. Экспорт полного содержания для редакторской миграции

Скрипт `extract-content.py` извлекает с **публичных исходных страниц** заголовки, абзацы, цитаты, списки, таблицы, ссылки и ссылки на изображения в отдельные JSON-файлы. Он не изменяет действующий сайт, не загружает изображения как файлы, не отправляет сообщения и не создаёт записи в CMS.

```bash
python3 -m pip install requests beautifulsoup4
# только статистика и проверка одного шаблона, без сохранения полного текста
python3 integration/extract-content.py --slug article
# сохранение в игнорируемый Git каталог для ручной сверки
python3 integration/extract-content.py --slug article --out integration/_exports
# полный пакет исходных страниц при наличии разрешения правообладателей
python3 integration/extract-content.py --all --out integration/_exports
```

Результаты по умолчанию отмечаются `editorialReviewed: false`, `rightsVerified: false`, `readyForPublication: false`. Имеют `sourceUrl`, дату извлечения и контрольную сумму `sourceHash`. Это позволит определить изменение первоисточника и не переносить незамеченные старые редакции.

**Обязательно:** проверить расположение медиафайлов и вложений, структуру подзаголовков, списков и ссылок. Не переносить полные тексты и изображения в публичный репозиторий без надлежащих прав. После утверждения использовать экспорт как вход в адаптер, а не вставлять материал вручную в исходники интерфейса.
