# Cosmatica 2026 — пакет полного редакционного содержания

Результат собирается из утверждённых публичных страниц РКО для новой визуальной системы. Источник маршрутов — таблица Павла, зафиксированная в [page-map.json](page-map.json). Новый сайт не использует серверный HTML, данные сессий, настройки базы или технические сообщения старой CMS.

## Что входит

- Все 31 контрольная исходная страница таблицы, дополненные вторым состоянием поиска — 32 интерфейса.
- Детальные страницы по всем обнаруженным ссылкам из каталогов первых уровней (новости, библиотека, проекты, отделения, партнёры, участники, события, статьи).
- Полные абзацы, заголовки, списки, таблицы, ссылки и выделение текста в структурированных JSON-записях.
- Изображения и доступные документы, сохранённые локально в `assets/source/`, чтобы новый сайт не зависел от прямой загрузки изображений старой Cosmatica.
- Поисковый индекс `data/search-index.json`, построенный из текстов всех импортированных записей.

Данные автоматически сохраняются в `data/source/*.json` и `data/linked/*.json`; связь исходного адреса с внутренней карточкой определяется `data/linked-index.json`. Число фактически выгруженных страниц и медиафайлов см. в `source-build-report.json`, `linked-build-report.json` и `asset-build-report.json`.

## Как пользоваться

Главная: `index.html`. Все остальные интерфейсы: `view.html?p=<slug>`, где `slug` указан в `page-map.json`. Дочерние страницы открываются ссылкой `view.html?p=<тип>&ref=<идентификатор>`. Задание `ref` или `item` должно приводить к *конкретному исходному материалу*. Если исходная карточка не найдена, демонстрация не должна подменять её другой статьёй или проектом.

При открытии `index.html` и `view.html` визуальные шаблоны используют `source-runtime.mjs`. Разделы с собственными работающими состояниями (вход, регистрация, поиск, календарь, пожертвования) сохраняют эти действия. Мобильная адаптация реализована в `source-runtime.css`, общие богатые текстовые блоки — в `rich-renderer.mjs`. Поиск — `source-search.mjs`.

Авторизация, реальный платёжный шлюз и отправка форм остаются вне статической демоверсии: их необходимо связать с действующими сервисами после переноса.

## Повторяемая сборка

GitHub Actions: `.github/workflows/cosmatica-editorial-build.yml`. Скрипт `build-editorial-snapshot.py` заново загружает одобренные публичные страницы, распознаёт списки, тексты и медиа и строит локальный пакет. После генерации `check-editorial-package.py` выполняет проверку состава, валидности JSON, локальных активов и исключения диагностических конфигураций.

```bash
python -m pip install requests beautifulsoup4 pillow
python integration/build-editorial-snapshot.py
python integration/check-editorial-package.py
```

Изменения данных фиксируются только в новой Git-ветке после прохождения проверки. Действующий сайт `cosmatica.org` не изменяется.

## Что следует проверить редактору

1. Дословность и порядок разделов больших статей, проектов, мероприятий и вкладок.
2. Корректность обложек, подрисуночных подписей, логотипов, файлов и прав на публикацию.
3. Актуальность персональных контактов, должностей, дат и сумм поддержки.
4. Отсутствие технических полей и внешних ссылок на исходный сайт в пользовательском интерфейсе.
5. Границы каталога: автоматическая сборка переносит утверждённые 31 страницы и связанные записи. Она не доказывает, что охвачен весь исторический архив CMS за все годы.
6. Недоступные для скачивания документы отображаются по названию без фиктивной кнопки скачивания.

**Полная визуально-информационная демоверсия не равна перенесённой серверной CMS.** Прежде чем заменять действующий сайт, необходимо выполнить редакторскую приёмку материалов и интеграцию серверных операций.
