# Cosmatica 2026 — руководство по передаче дизайна в разработку

Версия: итерация 02, 8 октября 2026. Рабочий дизайн-контур изолирован от действующего сайта `cosmatica.org`.

## Принцип реализации

Сохранить действующие маршруты и материалы сайта. Передавать Павлу не 32 независимые картинки, а библиотеку шаблонов, состояние каждого интерфейса и структурированные данные. Реальное содержимое должно поступать из CMS, а не навсегда оставаться в статическом JavaScript.

### Назначение файлов

| Файл | Назначение |
|---|---|
| `routes.js` | 32 интерфейса/состояния, заголовки и типы |
| `content.js` | Демонстрационные данные страниц, сведения из действующих материалов |
| `site.js` | Компоненты, шаблоны, маршрутизация, клиентские сценарии |
| `site.css` | Фирменный адаптивный слой, состояния desktop/mobile |
| `assets/rko-mark.svg` | Официальный знак РКО, без искажения или скругления |
| `index.html`, `view.html` | Входные HTML-оболочки |
| `sitemap.html` | Полная карта 32 интерфейсов |
| `INTERFACE_MATRIX.md` | Реестр всех интерфейсов |

## Проекты: модель шаблона

В `content.js` поле `project.variants` содержит пять реальных примеров:

- `gagarincy` — «Дружина Гагаринцев»: описание, цель, аудитории, направления, участники, документы, видео, новости, события и поддержка;
- `rusleo` — «Русский Леонардо»: фильм-киноурок, «Киноэкология», сбор средств с суммой и целью из исходной страницы;
- `sns` — «Союз Народного Сплочения»: информационный проект без финансового блока;
- `chotv` — «Чо-ТВ»: медиапроект, несколько внешних площадок;
- `slovo` — конкурс «ЖИВОЕ СЛОВО»: положение DOCX, тематика, участие, новости и мероприятия.

Для нового проекта шаблон получает из CMS минимум:

```json
{
  "id": "stable-id",
  "name": "Название",
  "fullName": "Официальное название",
  "status": "Действующий",
  "direction": "Направление",
  "mission": "Смысл и предназначение",
  "goal": "Цель",
  "history": "Сведения о деятельности",
  "image": "approved-image-url",
  "audiences": [],
  "science": [],
  "participation": [],
  "sections": [{"title": "Раздел", "body": "Содержимое"}],
  "fundraising": {"enabled": false},
  "documents": [{"label": "Документ", "url": "https://...", "type": "PDF"}],
  "links": [{"label": "Площадка", "url": "https://..."}],
  "stats": {},
  "sourceUrl": "https://cosmatica.org/projects/..."
}
```

Условия отображения: финансовый блок появляется только при `fundraising.enabled=true`; при отсутствии изображения не остаётся пустого контейнера; новости и события ссылаются на соответствующий проект; документы открывают реальный файл; количество полей может отличаться без изменения сетки.

Дополнительные проектные поля для интеграции с НС-2117 — **только при наличии подтверждённых данных**: связь с программой, территория, публичный результат, предшественники/преемники, следующий этап. Внутренние оценки и служебные поля в публичный интерфейс не выводить.

## Интерактивность и ограничения

В демонстрационном контуре работают: внутренняя навигация, переходы из каталогов, алфавит отделений, фильтрация статусов каталога проектов, переключение месяцев, поиск по локальным материалам, тёмная/светлая тема и мобильное меню.

Внешние функции авторизации, платежей, получения закрытого контента и публикации сообщений требуют серверных обработчиков и прав доступа. До подключения бэкенда соответствующие действия перенаправляют на действующий сайт РКО. Не вводить реальные платёжные данные и пароли в демонстрационный контур.

## Проверка перед переносом в production

1. Сверить все 32 интерфейса с `INTERFACE_MATRIX.md` и оригинальными URL.
2. Подключить актуальные текстовые и медийные материалы из CMS в `content.js` или через API; примерные данные не считать вечными.
3. Пройти desktop 1440 px, mobile 390 px, масштаб 200%, навигацию с клавиатуры.
4. Протестировать состояния пустых каталогов, отсутствующих картинок и ошибок запросов.
5. Проверить безопасность входа, CSRF, право доступа к закрытым данным и приём платежей на staging.
6. Протестировать обратную совместимость старых URL и редиректы.
7. Получить отдельное согласование перед заменой действующего сайта.
